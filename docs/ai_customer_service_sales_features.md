# 智能客服系統產品特色整理

## 產品定位

本系統是一套「受控型 AI 客服工具」，不是單純聊天機器人，而是可串接企業知識庫、帳務服務、Web、LINE 與真人客服流程的客服自動化平台。

系統核心設計是讓 AI 在明確規則、工具白名單與流程限制下協助客服作業，降低模型自由發揮造成的風險，避免亂承諾、亂代辦、亂收個資，同時保留自然語言互動的便利性。

## 一句話介紹

這套工具可以幫企業把官網與 LINE 客服升級成可控、可維護、可串接內部系統的 AI 客服平台，能自動回答常見問題、查詢帳務與服務資料、引導排錯、辨識帳單收據圖片，必要時再轉真人客服，降低客服量並提升服務效率。

## 核心特色

### 1. Web 與 LINE 多通路支援

系統支援官網 Web API 串接，也支援多個 LINE Bot 入口。不同通路會先整理各自的 channel context，再共用同一套 AI 客服核心。

可介紹重點：

- 官網、會員中心、活動頁可透過 API 串接 AI 客服。
- LINE 可依不同 Bot 或不同系統台分流。
- Web 與 LINE 不需要各自維護一套客服邏輯。
- 對話狀態與客服流程可跨回合延續。

### 2. 受控型 AI Router

使用者輸入後，系統會先由 Router 判斷需求，再分流到對應流程，例如知識查詢、帳務工具、排錯流程、公司資訊、真人客服或不支援流程。

可介紹重點：

- AI 不會直接亂呼叫功能，而是依白名單工具執行。
- 模糊問題會先反問，例如「帳單」會追問是查金額、補寄帳單或繳費方式。
- 未支援的代辦需求會明確告知限制，避免錯誤承諾。
- 可依企業服務項目擴充新的意圖與工具。

### 3. 企業知識庫 RAG

系統可使用企業內部知識庫回答問題，目前支援本地 ChromaDB RAG，知識來源可包含帳務、網路寬頻、機上盒、加值服務與內部流程文件。

可介紹重點：

- 回答依據企業知識庫，不只靠 AI 模型常識。
- 可上傳新文件並建立索引，讓知識持續更新。
- RAG 命中內容會整理成適合聊天室閱讀的重點摘要。
- 若知識庫命中但不對題，系統會避免硬套答案。

### 4. 知識庫維護後台

Web UI 已提供知識庫維護能力，可上傳文件、建立索引、列表、搜尋與維護知識文件。

可介紹重點：

- 客服、營運或內部人員可補充 FAQ 與流程文件。
- 不需要每次修改知識都調整 AI 程式。
- 可依不同系統台或通用知識分類管理。
- 適合持續補齊客服缺口。

### 5. 帳務與客戶服務工具串接

系統已設計多種客服工具流程，可串接企業既有 API，讓 AI 在驗證必要資料後執行查詢或送出申請。

目前可介紹的工具能力：

- 查詢未繳或需繳費帳單。
- 補發簡訊帳單或繳費單。
- 查詢合約內容、服務內容、到期日與申辦網速。
- 超商繳費後網路復線。
- 超商繳費後電視復線或授權確認。
- 使用超商繳費收據三段條碼確認繳費。
- 查詢頻道號，例如 HBO 頻道。
- 保留報修、取消報修、申裝、加值方案等擴充接口。

注意：目前部分代辦流程仍是停用或 mock 狀態，對外建議包裝為「可依客戶 API 串接後啟用」。

### 6. 圖片 OCR 辨識

系統提供獨立 OCR API，可辨識圖片中的文字，適合處理帳單、繳費單、超商收據或客服截圖。

可介紹重點：

- Web 可上傳 base64 圖片進行辨識。
- LINE 圖片訊息可下載後進入 OCR 流程。
- 可特別整理超商收據的第一段、第二段、第三段條碼。
- OCR 結果可再送回 AI 客服，接續後續流程。

### 7. 多系統台與多公司資料管理

系統內建多個系統台的公司資料，可依不同公司代碼回答對應資訊。

目前支援的公司/系統台包含：

- 大屯有線
- 中投有線
- 佳聯有線
- 北港有線
- 佳光電訊-西海岸區
- 佳光電訊-台中市區
- 新永安有線
- 大揚有線
- 台灣基礎開發

可回答的公司資訊：

- 公司地址
- 客服電話
- 營業時間
- 服務地區
- 服務產品
- 公司官網
- 加值服務網址
- 優惠活動
- 區域故障公告

### 8. 真人客服轉接

當使用者明確要求真人客服，系統可依通路進行對應處理。

Web 端：

- 回傳真人文字客服連結。
- Response 內帶出 `human_handoff` action，方便前端切換流程。
- 連結可帶會員識別、客編與加密 token。

LINE 端：

- 可切換真人客服模式。
- 後續使用者訊息不再進 AI，而是轉發到真人客服群組。
- 真人模式有逾時機制，超過時間後可恢復 AI 流程。

系統也會避免誤觸轉接。若使用者只是問「有真人嗎」，會先詢問是否真的要轉真人。

### 9. 對話狀態與紀錄保存

系統會自行保存使用者對話狀態、聊天紀錄與必要的 customer profile，不需要外部 Web server 每次帶回完整 history 或 ai_state。

可介紹重點：

- Web 第二輪之後只要傳同一個 `user_id` 即可延續對話。
- 登入會員與訪客都可支援。
- 本機測試環境可用 SQLite。
- 正式環境可切換 MongoDB。
- Web 與 LINE 可分 collection 保存，便於管理與稽核。

### 10. 企業級安全與營運控管

系統針對客服情境加入多項安全與營運控管。

可介紹重點：

- API token 驗證。
- 正式與測試環境設定切換。
- 客戶姓名、電話、客編驗證。
- 客編查詢可要求二次驗證。
- CUST API 呼叫時間與錯誤診斷紀錄。
- 對外回覆友善錯誤訊息，內部保留詳細 log。
- 工具白名單與不支援流程控管。

## 適合銷售的價值主張

### 降低客服量

常見問題、帳務問題、頻道查詢、繳費方式、公司資訊等可由 AI 自動處理，減少真人客服重複回答。

### 提升客服一致性

回答依據企業知識庫與公司資料，降低不同客服人員口徑不一致的問題。

### 保留流程控管

AI 不會無限制自由發揮，能依企業規則判斷哪些可以回答、哪些要追問、哪些要轉真人。

### 串接既有系統

可透過 API 串接帳務、會員、繳費、復線、真人客服等既有系統，不必推翻原有架構。

### 支援多品牌或多據點

同一套核心可服務多個系統台、多個 LINE Bot、多個公司資料，適合有多品牌、多區域服務的企業。

## 可對客戶說的版本

我們這套 AI 客服不是一般 FAQ Bot，而是以企業客服流程為核心設計的受控型 AI Agent。它可以接在官網與 LINE 上，依照使用者問題自動判斷是要查知識庫、查帳單、補寄帳單、處理復線、查頻道、辨識繳費收據，還是轉真人客服。

系統的重點是可控與可維護。企業可以上傳自己的知識文件、維護公司資訊與優惠活動，也可以串接既有帳務 API。AI 回答時會受到工具白名單、資料驗證與流程規則限制，不會亂辦理未知服務或收集不必要個資。

對企業來說，它能降低客服重複工作、提升回答一致性，並讓真人客服專注處理更複雜或高價值的問題。

## 銷售簡報可用條列

- AI 自動客服：支援官網與 LINE。
- 企業知識庫回答：可上傳文件並建立索引。
- 受控流程：AI 依規則判斷、追問、查詢、轉接。
- 帳務服務串接：查帳單、補寄帳單、合約查詢、復線流程。
- OCR 圖片辨識：可處理帳單與超商繳費收據。
- 真人客服轉接：Web 連結轉接、LINE 真人模式。
- 多公司支援：可管理不同系統台地址、電話、服務區與優惠。
- 狀態保存：系統保存對話紀錄與 AI 狀態。
- 正式部署友善：支援 API token、MongoDB、錯誤紀錄與環境切換。

## 對外說法注意事項

以下能力建議以「可串接後啟用」描述，不建議直接宣稱已完整自動代辦：

- 真實報修工單建立。
- 取消報修。
- 新申裝代辦。
- 服務地址可申辦查詢。
- 實際加值服務申辦。

建議對外說法：

「系統已保留相關工具流程與 API 擴充架構，後續可依客戶既有系統 API 串接後啟用。」
